# Security Policy

## Responsible use

RieaZuka is intended only for systems you own or systems for which you have explicit authorization to perform security testing. Keep scans within the declared scope and applicable rules of engagement.

The project intentionally avoids destructive or intrusive capabilities such as brute force, credential attacks, denial-of-service, persistence, stealth/evasion, malware, and automated exploitation.

## Reporting vulnerabilities in RieaZuka

Please avoid publishing an unpatched vulnerability in a public issue. Contact the maintainers privately through an appropriate repository security channel when available, include affected version, reproduction details using a harmless local test case, and suggested mitigation if known.

Do not include real credentials, private keys, tokens, personal information, or data taken from third-party systems in a report.
